## Платформа

- Вход через VK ID: кнопка в онбординге и в настройках, флоу в системном браузере, возврат по deep link. Кабинет VK ID: платформа «Веб», redirect `https://octus.fit/api/auth/callback/vk`, доступ к email включён — без почты вход падает. Локально вход не заработал. UX входа, выход, удаление, объединение документов и отвергнутый токен сделаны, устройство описано в `docs/sign-in/README.md`. На телефоне с настоящим VK проверены вход с первого экрана, выход и повторный вход в тот же аккаунт: анкета возвращается из аккаунта. Не проверены на телефоне:
  - вход из настроек, когда на телефоне уже есть тренировки, — объединение;
  - переустановка: вход возвращает тренировки.
- Вход через приложение VK вместо браузера. Сейчас VK ID открывается в Custom Tab и берёт сессию VK из Chrome; если человек залогинен только в приложении VK, ему придётся входить заново. Нативный VK ID SDK умеет вход через приложение.
- Бизнес-профиль VK ID подтверждён (самозанятый), 60-дневный срок верификации больше не висит.
- Локальные уведомления: сигнал таймера при заблокированном экране и напоминание о пропущенной тренировке. Именно локальные — серверные пуши не нужны и тянут за собой проблемы с FCM.
- RuStore-подписка: плагин Pay SDK и проверка на сервере готовы. Осталось после ИП: продукт с триалом в консоли, ID приложения в `rustore_console_app_id`, ключ API в `.env.prod`, гейт и экран покупки, кэш статуса на клиенте на оффлайн, серверные уведомления RuStore. См. `docs/rustore/README.md`.
  - Решить, нужна ли серверная проверка до входа. Анонимная сессия осталась только ради неё: покупка привязывается к пользователю Better Auth через `appUserId`, а документы анонимного пользователя на сервер больше не ходят. Если гейт держать на `getPurchases` из Pay SDK, а на сервер отправлять покупку только после входа, анонимная сессия не нужна вовсе, и вход через VK упрощается: не нужны одноразовый токен при старте и привязка анонимного пользователя. ## Техдолг

- Производительность запросов. `queryCollection` делает полный скан коллекции, а `useQueryCollection` подписан на всю коллекцию целиком — любая запись пересчитывает все активные запросы. Лечится индексами в сторе и инкрементальным обновлением по `event.changes.keys`, менять хранилище не нужно.
- `ModalStack`: `popstate`-слушатели не снимаются при размонтировании, условие сравнения по `location.state` хрупкое при быстром двойном «назад». Концепцию (модалка = запись в history) оставить.
- Yjs не трогать до появления платящих пользователей. Апдейты схлопываются в одну строку каждые 100 записей, но история внутри документа всё равно растёт монотонно — позже понадобятся снапшоты и её обрезка.
- README описывает приложение как инструмент совместной работы в реальном времени. Это одиночное приложение, переписать.
