# Рекомендации

Как приложение выбирает вес, повторы и разминку. Числовые коэффициенты
каталога — в [starting-weights.md](starting-weights.md).

Документ описывает решение целиком, включая то, чего пока нет в коде. Сейчас
`buildRecommendations` — заглушка, возвращающая вес прошлого раза.

## Две задачи, а не одна

**Прогрессия** работает, когда у упражнения есть история: двойная прогрессия,
детерминированная, объяснимая одной строкой.

**Прикидка** работает, когда истории нет: первое упражнение новичка, новое
упражнение после полугода тренировок, возврат после перерыва.

Это разные задачи, и смешивать их не надо. Прикидка обязана ошибаться — она
угадывает. Поэтому у неё есть страховка: режим подбора, который находит
настоящий вес за одну-две тренировки.

## Одна механика на всё

Любой пересчёт «вес ↔ повторы» идёт через оценку разового максимума по Эпли:

```
1ПМ = вес × (1 + повторы / 30)
вес = 1ПМ / (1 + повторы / 30)
```

Одна формула на весь диапазон повторов. Гибрид с Бжицки, который стоял в коде
для повторов до 10, убирается: он даёт 3.4% веса на повтор против 2.8% у Эпли,
то есть систематически завышает шаг прогрессии. Отдельно обрабатывается
`повторы = 1`: у Эпли там получается 1ПМ на 3% выше поднятого веса, что в
рекордах видно и неверно — считаем 1ПМ равным весу.

Практическое следствие формулы — константа, на которой держится всё остальное:

> **Один повтор ≈ 2.5% веса.**

Она же задаёт разрешающую способность всех правил. Два повтора — это 5%, то
есть примерно один блин 2.5 кг на штанге 60 кг. На недобор в один повтор
реагировать нечем: такого шага в инвентаре нет. Поэтому ни одно правило ниже
не различает единичный повтор — не из-за упрощения, а потому что
**правило не может быть тоньше шага блинов**.

## Прикидка веса

### Четыре якоря

Уровень человека описывается четырьмя числами — 1ПМ жима лёжа, приседа,
становой и подтягиваний. У подтягиваний это полный вес: собственный плюс
отягощение.

Опытный вводит их в онбординге, целиком или частично. Новичок не вводит
ничего: якоря считаются от пола и веса тела. Базовые значения — в
[starting-weights.md](starting-weights.md).

### Доля от якоря

Каждое упражнение каталога объявляет `strength: { ref, factor }` — свой 1ПМ
как долю от одного из якорей.

**Якорь — это линейка, а не утверждение о мышцах.** Выбирается он по тому,
отношение к какому из четырёх лифтов держится устойчиво на всех уровнях.
Связь там популяционная, а не физиологическая: у кого большой присед, у того
обычно и жим ногами, потому что люди тренируют и то и другое.

Из этого следуют два правила. Первое: когда два лифта одинаково устойчивы,
**берём ближайший по движению** — тянущее к тянущему. Второе: якорь **не
годится для выбора донора** в пункте 2 цепочки ниже, там смотрим на мышцы.

У упражнений со своим весом (`weight: positive | negative`) доля считается от
полного веса — собственный плюс отягощение. Якорь у них обычный, по движению.

```
1ПМ упражнения = якорь × доля
вес входа      = 1ПМ / (1 + min повторов / 30)
```

Числа и разбор по упражнениям — в [starting-weights.md](starting-weights.md).

### Откуда берётся оценка

Цепочка источников, сверху вниз. Первый сработавший выигрывает:

1. **История самого упражнения** — с затуханием, см. ниже.
2. **Ближайшее по мышцам упражнение с историей.** Источник измеренного 1ПМ —
   коллекция `records`, тип `one_rep_max`, она уже ведётся.

   ```
   новый = измеренный_донор × (предсказанный_новый / предсказанный_донор)
   ```

   То есть «насколько человек сильнее ожидаемого в этом движении», перенесённое
   на соседа. Якорь в формуле сокращается, поэтому донор и цель не обязаны
   ссылаться на один якорь.

3. **Якоря онбординга × доля** — то, с чего начали.

**Якоря онбординга не обновляются никогда, и это главное свойство цепочки.**
Соблазн есть: человек тренируется полгода, можно же пересчитать его уровень по
накопленным данным. Нельзя — потому что уровень не общий. Полгода жимов не
делают ноги сильнее, и приложение не должно так думать. Группа, которую не
тренировали, остаётся новичковой сколько угодно долго, и первый подход в ней
считается по анкете.

Из того же следует, что донор выбирается **по мышцам, а не по якорю**:
приседания предсказывают фронтальные приседания, а жим лёжа — не предсказывает
тягу блока, сколько бы ни совпадали их числа в популяции.

Любой источник кроме первого даёт **оценку, а не факт**: умножаем на 0.85 и
включаем режим подбора. Промах вниз стоит одной тренировки подбора, промах
вверх — проваленного подхода и, возможно, ушедшего пользователя. Асимметрия
огромная, играем в одну сторону.

### Затухание

История упражнения стареет:

| Перерыв | Множитель |
|---|---|
| до 2 недель | 1.0 — обычная жизнь |
| 2–8 недель | 0.97 за каждую неделю сверх второй |
| больше 3 месяцев | история не используется, идём в пункт 2 цепочки |

Пол — 0.7: больше трети лифта за реальный срок не теряется, а подбор доберёт
остальное вверх за одну тренировку.

Верх и низ тела **не разделяем**. Ноги детренируются быстрее, это правда, но
подбор исправляет ошибку внутри одной тренировки, так что точность затухания
почти ничего не покупает, а правило усложняет.

### Отсев упражнения

> Если расчётный вес не превышает минимальный собираемый, упражнение не
> предлагается. Берём альтернативу из графа `alternatives`, приоритет —
> многосуставные на тренажёрах и блоках.

Триггер бесплатный: расчёт сам сообщает, что упражнение не проходит. Это
закрывает подтягивания и брусья для новичков (уходят в гравитрон), штангу для
женщин там, где в зале нет лёгкого грифа, и подъём на бицепс для
новичка-мужчины (уходит на гантели).

## Подбор веса

Прикидка обязана ошибаться, поэтому у неё есть страховка.

**Подбор — выводимое состояние, а не поле в базе.** Упражнение подбирается,
пока ни один его рабочий подход не попал внутрь диапазона с оценкой «норм» или
«тяжело». Выводится из истории, не может протухнуть, не требует флага.

Пока идёт подбор, вес меняется **внутри тренировки, от подхода к подходу**:

| Результат подхода | Дальше |
|---|---|
| взял верх диапазона, «легко» | ×1.3 |
| взял верх, «норм» | ×1.15 |
| взял верх, «тяжело» | держим, подбор закончен |
| попал внутрь диапазона | держим, подбор закончен |
| ниже низа диапазона | ×0.85, подбор закончен |

Оценка подхода уже собирается на экране отдыха. **Если её не поставили** —
выводим из повторов: взял верх → ×1.15, ниже низа → ×0.85. Оценка усиливает
алгоритм, но не является его условием; большинство её не тыкает.

Пример. Новичок посажен на 20 кг, реально может 50, диапазон 6–8:

```
Тр. 1:  20×8 легко  →  27.5×8 легко  →  35×8 легко  →  (45 на следующую)
Тр. 2:  45×8 норм   →  52.5×7 тяжело →  подбор закончен на 52.5
```

Две тренировки. Слабый новичок с реальными 27 кг:

```
Тр. 1:  20×8 легко  →  27.5×6 тяжело →  подбор закончен на 27.5
```

Никого не раздавило: повторы вводит человек, оценку ставит человек, худший
исход — один тяжёлый подход.

**Управляющий принцип, который отделяет подбор от обычной работы:**

> Вверх вес внутри тренировки двигается только в режиме подбора.
> Вниз — всегда.

Рост внутри тренировки ломает контракт двойной прогрессии («все рабочие
подходы одного веса») и сбивает с толку, поэтому он заперт в явном режиме.
Снижение ничего не ломает: продолжать с весом, который не идёт, хуже любой
несогласованности.

В UI подбор показывается плашкой «подбираем вес». Та же плашка обслуживает
длинный перерыв — «вспоминаем вес». Поводов войти в подбор три — новое
упражнение, перерыв, промах прикидки, — а режим для человека один.

## Прогрессия

Двойная прогрессия: набираем повторы во всех подходах до верха диапазона,
потом поднимаем вес.

### Три события

| Событие | Условие | Действие |
|---|---|---|
| **Шаг вперёд** | все рабочие подходы взяли `max`, провалов не было, выполнение не прервано | вес на `min` повторов при том же 1ПМ |
| **Провал** | подход не добрал до `min` **2 и более повтора** | снижение внутри тренировки, см. ниже |
| **Шаг назад** | был провал, либо 3 тренировки подряд без выхода на `max` | одна прибавка, но вниз |

Всё. Никаких сумм повторов, никаких отдельных процентов делоада. Провал и
застой — два разных повода для одного и того же шага назад.

### Шаг вперёд

```
новый вес = 1ПМ(текущий вес, max), пересчитанный на min повторов
```

Для 6–8 это ×1.056, около 5%. Фактический шаг берётся минимальный, который
может собрать инвентарь, но не больше расчётного.

### Провал и снижение внутри тренировки

```
новый вес = 1ПМ(вес, сделанные повторы) × 0.975, пересчитанный на max повторов
```

Две поправки, обе намеренные. **Множитель 0.975** — усталость: следующий
подход будет тяжелее того, который только что провалился. **Целимся в `max`,
а не в `min`** — снижаемся мы потому, что впереди ещё подходы и мы продолжим
уставать; метить в тяжёлый край диапазона, уже провалившись, бессмысленно.

Округление — **до ближайшего**. Мы уже заложились дважды, третий пессимизм
подряд даст слишком лёгкий вес.

Упражнение при этом **не останавливается**. Оставшиеся подходы на сниженном
весе всё ещё дают стимул, а решение «на сегодня хватит» должен принимать
человек, а не приложение.

Пример, диапазон 6–8, вес 60, подходы 8, 6, 4:

```
1ПМ(60, 4)  =  60 × 1.1333  =  68.0
усталость      68.0 × 0.975 =  66.3
вес на 8       66.3 / 1.2667 = 52.3  →  52.5
```

Четвёртый подход идёт на 52.5.

### Почему порог провала считается в повторах

Порог и величина отвечают на разные вопросы, поэтому меряются по-разному.

«Пора ли снижать» — вопрос про диапазон: подход выпал из него настолько, что
это не шум. Метрика — повторы, порог — два до `min`.

«На сколько снижать» — вопрос про то, куда целиться, и он решается формулой.
Вывести из формулы ещё и порог нельзя: она требует большого снижения при любом
недоборе, потому что целится в `max`. Подход на 5 повторов при цели 6–8 дал бы
по ней −6 кг, хотя 8, 7, 6, 5 — это нормальная тренировка.

### Следующая тренировка после провала

**Шаг назад на одну прибавку, а не сниженный вес.** В сниженном весе сидит
поправка на усталость: он про «дотянуть сегодня», а не про «сколько я могу
свежим». Если запоминать его как прескрипшн, людей будет систематически
стаскивать вниз — каждая неудачная тренировка зафиксирует вес заведомо ниже
реальной возможности.

### Разобранные случаи

Диапазон 6–8, вес 60, четыре рабочих подхода, шаг инвентаря 2.5:

| Результат | Внутри тренировки | Следующая |
|---|---|---|
| 8, 8, 8, 8 | — | **62.5** |
| 8, 7, 6, 5 | — | **60**, застой +1 |
| 8, 6, 4 | провал на 3-м → 4-й на 52.5 | **57.5** |
| 5, 5, 5, 5 | — | **60**, застой +1 |
| 8, 6, 2 | провал на 3-м → 4-й на 50 | **57.5** |

Диапазон 12–20, вес 48, три подхода, результат 20, 12, 4: провал на третьем
(недобор 8), расчётное снижение до 31.8 — дальше по инвентарю, следующая
тренировка — шаг назад.

### В UI

Условие прибавки показывается буквально: **«верх взяли 2 подхода из 4»**.
Это и есть правило, а не его пересказ.

Снижение и шаг назад **всегда подписаны**: «вес снижен, в прошлый раз не
набралось повторов». Молча упавший вес читается как баг.

## Ширина диапазона повторов

> Диапазон подобран верно, когда переход с `max` на `min` стоит примерно один
> шаг снаряда.

Это тот же предел, что и порог провала, вид сбоку: реагировать тоньше, чем
умеет инвентарь, невозможно. Для штанги 60 кг с шагом 2.5 это 4.2% ≈ 1.5
повтора, отсюда 6–8. Для гантели 20 кг с шагом 2 — 10% ≈ 4 повтора, отсюда
8–12. Для стека 40 кг с шагом 5 — 12.5% ≈ 5 повторов, отсюда 10–15.

Каталог уже так и устроен, поэтому правило записано как инвариант для ревью
новых упражнений, а не как изменение.

**Расширение в рантайме.** Если инвентарь конкретного зала грубее ожидаемого и
минимальный шаг уронил бы повторы ниже `min`, либо шага нет вообще (свой вес
без утяжелений), диапазон расширяется вверх до красивого значения: 6–8 → 6–12.
Поле для этого уже есть — `Performance.reps`.

## Разминка

### Два разных смысла

**Разогрев** — ткани, суставы, ЦНС. Нужен один раз за тренировку на область.
Лёгкий вес, много повторов, пирамида.

**Прострел траектории** — найти позицию под новым углом. Разогрев уже есть,
новая только позиция. Близко к рабочему весу, мало повторов, один подход.

Отсюда таблица, две независимые проверки:

| Мышцы | Траектория | Оборудование | Разминка |
|---|---|---|---|
| холодные | — | — | пирамида, число подходов ниже |
| горячие | новая | свободный вес | **1 подход, 80% × 3** |
| горячие | новая | тренажёр, блок | 0 — траекторию держит рама |
| горячие | та же | — | 0 |

«Мышцы горячие» считается по `primaryMuscles` и `secondaryMuscles` предыдущих
выполнений этой тренировки — данные в каталоге уже есть. «Траектория» требует
нового тега `pattern`.

Жим → наклонный жим → разгибания на блоке даёт ровно то, что ожидается:
пирамида, один прострел, ноль.

### Сколько подходов в пирамиде

Число подходов определяется отношением рабочего веса к **весу, который по
расчёту был бы нормальным для новичка** в этом же упражнении — то есть к
столбцу «новичок» из [starting-weights.md](starting-weights.md).

| Рабочий вес / вес новичка | Подходов |
|---|---|
| < 0.75 | 0 |
| < 1.25 | 1 |
| < 2 | 2 |
| < 2.5 | 3 |
| ≥ 2.5 | 4 |

Отношение значит «во сколько раз ты сильнее новичка в этом движении», и это
рабочий прокси абсолютной нагрузки на сустав. Важно, что он **не требует ни
одного нового коэффициента**: таблица для первого веса уже посчитана.

Отношение к минимальному собираемому весу для этого не годится. Для штанги оно
работает случайно, потому что гриф — константа; на стеке с минимумом 5 кг и
шагом 5 оно улетает за 10 и требует четырёх разминок к тяге верхнего блока.

Проверка на живых числах (новичок-мужчина: жим 37.5, тяга блока 30):

| Ситуация | Отношение | Подходов |
|---|---|---|
| жим 20 (пустой гриф) | 0.53 | 0 |
| жим 40 | 1.07 | 1 |
| жим 60 | 1.60 | 2 |
| жим 100 | 2.67 | 4 |
| тяга верхнего блока 50 | 1.67 | 2 |
| тяга верхнего блока 60 | 2.00 | 3 |

Отсюда видно, что **разминка чувствительна к столбцу «новичок»**: тяга блока
на 60 кг стоит ровно на пороге, и сдвиг доли на одну плитку переводит её из
двух подходов в три. Это цена того, что мы переиспользуем таблицу первого веса
вместо отдельных коэффициентов, и она приемлема — ошибка стоит одного лишнего
разминочного подхода, а не проваленного рабочего.

Упражнения со своим весом считаются на полном весе через `addSelfWeight`,
иначе арифметика бессмысленна: у гравитрона числа идут вниз, а у подтягиваний
пол разминки — собственный вес, поэтому пирамида там коротка по построению.

**Что этот подход не различает** — штангу и тренажёр при равном отношении.
Приседу нужно больше разминки, чем жиму ногами. Это единственный оставшийся
зазор; чинится битом «+1 подход штанговым компаундам», если на практике
окажется заметно. Заранее не добавляем.

### Веса и повторы пирамиды

| Подходов | Проценты от рабочего | Повторы |
|---|---|---|
| 1 | 55 | 8 |
| 2 | 55, 80 | 10, 5 |
| 3 | 45, 65, 85 | 10, 5, 3 |
| 4 | 30, 50, 70, 85 | 10, 6, 4, 2 |

Разминочные веса округляются **вниз** и схлопываются при совпадении: на грубом
инвентаре два процента дают один вес. Пол — минимальный собираемый вес.

Жим 60 даёт 32.5 и 47.5. Жим 40 даёт один подход на 20, то есть пустой гриф.

## Брошенное упражнение

Человек может прекратить упражнение посреди тренировки — заболело колено,
заняли тренажёр, кончилось время. Незавершённые подходы при этом **не
удаляются**: упражнение должно остаться в следующих тренировках.

```ts
// Время, когда человек сознательно закончил упражнение раньше плана.
stoppedAt?: number;
```

Причину не спрашиваем: случай редкий, а разбор причин добавляет ветвлений
больше, чем приносит пользы.

Как это читает прогрессия:

- сделанные подходы засчитываются как есть — повторы настоящие;
- «все подходы взяли `max`» считается по выполненным, а не по запланированным;
- **шаг вперёд требует, чтобы выполнение не было прервано**, иначе прибавку
  можно получить, сделав один подход и уйдя;
- счётчик застоя не трогается.

Заодно чинится текущая дыра: сейчас «не доделал» и «ещё делаю» неотличимы.

## Структура данных

### Профиль

Пола нет нигде — `Measurement` знает только вес и рост. Если масштабировать
одним весом тела, первый вес в жимах для женщин завышается более чем
в полтора раза: 36 кг вместо 22.

```ts
export type AnchorId = "bench" | "squat" | "deadlift" | "pullup";

export interface Profile {
  id: string;
  user: string;

  sex: "male" | "female";
  birthYear?: number;

  // Влияет только на то, спрашиваем ли якоря.
  experience: "none" | "past" | "current";

  // 1ПМ в кг, заполняется частично или не заполняется вовсе.
  // У pullup — полный вес: собственный плюс отягощение.
  // Записывается один раз в онбординге и больше не пересчитывается.
  anchors?: Partial<Record<AnchorId, number>>;
}
```

Блок «кто ты» стоит сразу отделить от будущего блока «чего хочешь» (частота,
сплит, доступное оборудование): первый нужен рекомендациям, второй — сборщику
программ, и добавление второго не должно переделывать первый.

### Каталог

```ts
// Доля от 1ПМ якоря. Для weight: positive | negative — от полного веса.
strength: { ref: AnchorId; factor: number };

// Траектория движения, ~15 значений. Нужна разминке, пригодится
// сборщику программ: «вертикальное тянущее сегодня уже было».
pattern: MovementPattern;
```

### Выполнение

```ts
stoppedAt?: number;
```

### Собственный вес тренажёра

`load: { type: "plates" }` сейчас считает только блины — в
`src/client/db/exercises/types.ts` это записано как сознательное решение: вес
каретки на тренажёрах не пишут. Для рекомендаций это решение придётся
отменить.

Виден дефект на ягодичном мостике в тренажёре: полная нагрузка в таблице
оценена верно, но выражена она в блинах, а платформа добавляет к ней десятки
килограммов. То же у жима ногами, гакк-машины и плитных жимов от груди.
Поправкой в долю это не лечится: доля — отношение сил человека, а собственный
вес тренажёра к силам человека отношения не имеет и в разных залах разный.

Значит, у станков с платформой нужен **базовый вес, как гриф у штанги**:

```ts
| { type: "plates"; sides: 1 | 2; base?: number }
```

Настраивается он, как `Gym.stacks`, — по упражнению, потому что отличается от
машины к машине. Оценка и прогрессия тогда работают с полной нагрузкой, а
калькулятор блинов продолжает показывать то, что человек реально вешает.

Пока не реализовано: доли в [starting-weights.md](starting-weights.md) для
таких упражнений считаются по блинам и занижают полную нагрузку.

### Передача блочных тренажёров

Число на стеке не равно усилию: часть станков стоит с передачей 2:1, и одно и
то же упражнение в другом зале читается вдвое тяжелее. Спрашивать передачу
бесполезно — её не знает никто, включая тех, кто там тренируется.

Отдельного механизма это не требует, и угадывать передачу по данным не нужно.
Разбор по случаям:

- **Первый заход на блочное упражнение.** Предсказываем как для 1:1, на станке
  2:1 выходит вдвое легко, подбор поднимает за одну тренировку. Промах в
  безопасную сторону.
- **Обычная прогрессия.** Всё считается от измеренного веса, передача
  сокращается.
- **Зал только с тренажёрами.** Оценки смещены, но одинаково для всех станков
  этого зала, то есть внутри зала согласованы.

Остаётся один настоящий случай — **смена зала**. Лечится тоже без знания
передачи: блочные упражнения уходят в подбор, как после длинного перерыва и с
той же плашкой, свободные веса переносятся без изменений. Пока зал один, это
неважно; когда появится второй, понадобится.

Заодно это объясняет, почему шаг стека можно не пересчитывать: производители
размечают плитки так, что **ощущаемый шаг выходит сопоставимым** — 5 кг на
стеке при 2:1 это 2.5 кг усилия, 5 фунтов при 1:1 — 2.27 кг. Инвариант
«ширина диапазона повторов соответствует шагу снаряда» держится в обоих залах
без поправок.

### Что ещё блокирует

`tracking: "weight_reps" | "reps" | "time" | "distance"` у упражнения — из
[design/README.md](../../design/README.md). Планка и подтягивания без веса
ломают экран с двумя числами, и прогрессия по весу для них не определена.

### Доступ к данным

Вопрос отложен. Понятно, что `RecommendationParams` в текущем виде мало: нужны
история слота на несколько выполнений назад, профиль, рекорд `one_rep_max` и
выполнения ранее в этой тренировке. Интерфейс
`buildRecommendations(params) => RecSetData[]` при этом остаётся.

## Чего не делаем

- **Никакого RPE, скоростей и подгонки кривых.** В оценке подхода четыре
  кнопки, это потолок точности входа.
- **Никакой автопрогрессии за пропущенные тренировки.** Не были в зале — вес
  не вырос.
- **Никаких молчаливых изменений.** Снижение и шаг назад подписаны словами.
- **Никаких правил, которые нельзя объяснить одной строкой.** Если правило не
  помещается в подпись под числом, оно слишком умное — выкидываем.
