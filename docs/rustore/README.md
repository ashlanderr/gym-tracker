# RuStore

Как выложить приложение в RuStore и продавать подписку. Документация
изучена 29 сентября 2026 года; ссылки — внизу.

## Главное: самозанятому продавать нельзя

С 1 февраля 2026 года платёжные инструменты RuStore (платные приложения,
подписки, покупки внутри приложения) доступны только ИП и юрлицам. У
самозанятого Pay SDK не работает, платные приложения скрываются с витрины,
списания по подпискам останавливаются. Публиковать и обновлять бесплатные
приложения самозанятый может.

Отсюда порядок работ:

1. Публикуемся как есть, самозанятым, бесплатным приложением. Это
   закрывает всё, что не про деньги: подпись, модерация, карточка, политика
   конфиденциальности.
2. Перед подпиской — стать ИП. Регистрация бесплатная, 3–5 дней в налоговой
   плюс около 3 дней на постановку на учёт. Нужна усиленная
   квалифицированная электронная подпись (Рутокен). Налог на НПД 4–6%
   сохраняется и для ИП. Затем письмо в support@rustore.ru с темой
   «Сохранить текущий VK ID и обновить правовой статус»: 1–2 рабочих дня,
   приложения переезжают в аккаунт ИП, новые версии выпускать не нужно.
3. Встраиваем Pay SDK и серверную проверку.

Комиссия RuStore — 15%.

## Публикация

Требования консоли:

| Что | Требование | У нас |
|---|---|---|
| Файл | APK или AAB, до 5 ГБ, подписан | подписанный APK, см. «Подпись» |
| Версии | та же подпись, `versionCode` больше предыдущего | из `package.json`, см. «Версия» |
| Название | до 30 символов, уникальное, совпадает с установленным | «Октус — дневник тренировок», 26 символов; в лаунчере «Октус» — уточнить у модерации, допустимо ли |
| Краткое описание | до 80 символов | нет |
| Полное описание | до 4000 символов, по-русски | нет |
| Иконка | 512×512, PNG/JPG, до 3 МБ, совпадает с иконкой лаунчера | есть исходник `pwa-assets/logo.png` |
| Скриншоты | от 3 на тип устройства, 9:16 или 16:9, реальный интерфейс, не только сплэш или логин | нет |
| Контакты | хотя бы один: почта, группа VK, сайт, MAX | нет |
| Политика конфиденциальности | обязательна | https://octus.fit/privacy/ (`landing/privacy/`) |
| Возрастной рейтинг, категория | выбрать в консоли | «Спорт» |

Правила модерации, которые нас касаются:

- Подписка: часть функций должна работать без неё, цена показана заранее.
  Совпадает с разделением free/paid из TODO.
- Вход: модератор должен пройти авторизацию без сторонних ресурсов;
  тестовый доступ пишется в комментарии для модератора. У нас вход
  необязательный, приложение работает на анонимном аккаунте.
- Без кликбейта в названии («лучший», «единственный»), без чужих товарных
  знаков в описании. Риск по знаку «Октус» — в
  `design/branding/README.md`.

### Подпись

Release-ключ — `octus-release.jks` (PKCS12, RSA 4096, алиас `octus`,
действует до 2054 года). Он лежит вне репозитория, основная копия — в
менеджере паролей. Потеря ключа означает, что обновления больше не выпустить:
RuStore принимает новую версию только с той же подписью. Тот же ключ нужен
для проверки платежей: Pay SDK требует подпись, совпадающую с приложением в
консоли.

Отпечатки сертификата — их спрашивают консоли RuStore и VK ID:

```
SHA-1   50:D5:73:D8:A3:A4:37:A2:D2:6B:9C:2D:6E:82:6F:09:1E:D1:7B:F9
SHA-256 B8:E2:0D:2C:6E:69:24:F5:3D:C8:D4:0D:77:74:B0:E9:88:C2:32:C3:3A:64:4A:EF:9B:9C:0B:43:09:E4:71:0D
```

Gradle читает ключ из `android/keystore.properties` (в `.gitignore`):

```properties
storeFile=C:/path/to/octus-release.jks
storePassword=...
keyAlias=octus
keyPassword=...
```

Без этого файла `npm run apk:release` останавливается сразу. Для CI
достаточно записать этот файл из секретов перед сборкой.

Сдаём APK, а не AAB: подписываем сами, в консоль уходит тот же файл, что
ставится на телефон для проверки.

### R8

Release собирается с `minifyEnabled` и `shrinkResources`. APK вместе с Pay
SDK — 4,2 МБ против 4,7 МБ без SDK и без R8; dex — 1,9 МБ вместо 7.
Своих правил в `proguard-rules.pro` не понадобилось: Capacitor и Pay SDK
приносят consumer rules. Проверено на эмуляторе на debuggable-сборке с
R8: приложение стартует, синхронизируется, все методы плагина отвечают,
платёжная шторка открывается.

### Версия

Единственный источник — `version` в `package.json`. Vite вшивает её в
клиент (`APP_VERSION`, экран настроек), Gradle — в `versionName` и
`versionCode = major·10000 + minor·100 + patch`. Минор и патч должны быть
меньше 100, иначе сборка падает. Каждой новой загрузке в стор нужен новый
номер. Нумерация начата заново с 1.0.0: до стора было внутреннее 4.10.1.

### Выкладка новой версии

Первую версию и карточку заводим руками в консоли: API добавляет версии
только к существующему приложению. Дальше:

1. Поднять `version` в `package.json`.
2. GitHub → Actions → Release → Run workflow, «что нового» и галочка
   publish. Workflow собирает подписанный APK, кладёт его в артефакты и,
   если отмечено, вызывает `npm run rustore:publish`: черновик → APK →
   модерация. Публикация остаётся ручной (`publishType: MANUAL`) — после
   одобрения нажать кнопку в консоли.

Если в консоли уже висит черновик, скрипт останавливается: черновик один
на приложение, и в нём могут быть ручные правки.

Секреты репозитория для workflow:

| Секрет | Что |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 octus-release.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | пароль keystore, он же пароль ключа |
| `RUSTORE_KEY_ID` | id ключа API из консоли |
| `RUSTORE_PRIVATE_KEY` | приватный ключ API из консоли |

Методы сверены с документацией 29 сентября 2026 года:
`GET /public/v1/application/{package}/version?versionStatuses=DRAFT`,
`POST .../version` (черновик, в ответе id), `POST .../version/{id}/apk?isMainApk=true`
(multipart, поле `file`), `POST .../version/{id}/commit`. Загрузка и
отправка на модерацию отвечают без `body`.

## Подписка: Pay SDK

Старый BillingClient SDK выключен 1 августа 2026 года, платежи через него
не проходят. Актуален только Pay SDK, сейчас версия 11.1.0.

- Нативный SDK — Kotlin/Java: `ru.rustore.sdk:pay` через BOM
  `ru.rustore.sdk:bom:2026.08.01`. Есть обёртки для React Native, Flutter,
  Unity и других, для Capacitor нет. Найденный
  `maningame/capacitor-rustore-billing` построен на мёртвом BillingClient.
  Значит, пишем свой локальный Capacitor-плагин в `android/` — тонкую
  обёртку над `getProducts`, `getPurchases`, `purchase`.
- В манифест: `meta-data` с ID приложения из консоли и deep link-схема для
  возврата из оплаты. Схема нужна и для входа через VK ID — завести одну на
  оба случая.
- Установленный RuStore не обязателен: SDK умеет платить через СБП и
  банковские приложения, покупать можно без авторизации в RuStore.
- Подписки — только одностадийный платёж. Периоды настраиваются в консоли:
  пробный, промо, основной, grace и hold. Триал и грейс-период на неудачное
  списание — это настройка продукта, не наш код.
- Песочница с тестовыми картами. Карта с балансом 1 копейка проверяет
  переход в grace/hold после триала.

### Как устроено у нас

- `android/.../RuStorePayPlugin.java` — плагин Capacitor на Java: модели
  SDK — обычные классы, Kotlin не нужен. Методы: `checkAvailability`,
  `getProducts`, `purchase` (одностадийная), `getSubscriptions`.
  Сигнатуры сверены с `classes.jar` из AAR 11.1.0, а не только с сайтом.
- `src/client/native/rustore-pay.ts` — типы для клиента.
- Подписки читаются через `getPurchases(SUBSCRIPTION)`.
  `getBillingSubscriptions` — только для подписок старого BillingClient.
- `MainActivity` передаёт в SDK входящие intent. `BridgeActivity`
  прогоняет стартовый intent через `onNewIntent` при каждом создании
  Activity, а SDK нельзя показывать его повторно при пересоздании — отсюда
  флаг `restoring`.
- Схема deep link — `ru.ashlanderr.gymtracker` (`custom_url_scheme`), её
  же использовать для VK ID.
- ID приложения из консоли — `rustore_console_app_id` в
  `res/values/strings.xml`, пока пустой. Пустой ID приложение не роняет:
  SDK отвечает `RuStorePaymentNetworkException: Application not found`.
- В `appUserId` покупки передаём id пользователя Better Auth: по нему
  сервер сопоставит покупку с аккаунтом.
- SDK тянет свою аналитику, метрики и сборщик крашей VK (`tracer`) и ходит
  в сеть при старте. Это отражено в политике конфиденциальности.

## Сервер

Статус подписки решает сервер, клиент только кэширует его на оффлайн.
Сверено с документацией API 29 сентября 2026 года.

- Ключ API создаёт владелец или администратор компании в консоли: вкладка
  компании → «API RuStore». Консоль отдаёт `keyId` и приватный ключ —
  base64 от PKCS#8 DER без PEM-обёртки. На сервере это `RUSTORE_KEY_ID` и
  `RUSTORE_PRIVATE_KEY`; без них сервер работает, но `subscription.verify`
  отвечает `PRECONDITION_FAILED`. В прод их положить через
  `dotenvx set ... -f .env.prod`.
- Авторизация: `POST /public/auth/` с `keyId`, `timestamp` (ISO 8601 с
  миллисекундами, расхождение с часами RuStore не больше 60 секунд) и
  `signature` = SHA512withRSA от `keyId + timestamp` в base64. В ответе
  JWE-токен на 900 секунд, дальше он идёт в заголовке `Public-Token`.
  Клиент кэширует токен и обновляет его за минуту до конца.
- Проверка подписки: `GET /public/v5/subscription/{packageName}/{productId}/{purchaseId}`,
  для тестовых покупок — `/public/sandbox/v5/...`. Метод работает только с
  подписками Pay SDK. Нам нужен `expiryTimeMillis`; `paymentState`: 0 —
  ждёт оплаты, 1 — оплачено, 2 — триал.
- `appUserId` этот метод не возвращает (есть в `GET /public/v2/invoices/{invoiceId}`).
  Поэтому покупка закрепляется за аккаунтом, который прислал её первым:
  `purchaseId` — первичный ключ таблицы `subscription`, второй аккаунт с
  тем же id получает `FORBIDDEN`.
- Тестовые покупки из песочницы сервер тоже засчитывает и помечает
  `sandbox`. Делать их могут только тестировщики из консоли.

Код: `src/server/rustore.ts` (клиент API), `src/server/subscriptions.ts`,
процедуры `subscription.status` и `subscription.verify` в `router.ts`.

Не сделано:

- Серверные уведомления RuStore о смене статуса. Пока сервер узнаёт о
  продлении, только когда приложение снова присылает покупку.
- Кэш статуса на клиенте с грейс-периодом на оффлайн и сам гейт: какие
  функции платные — продуктовое решение.

## Не проверено

- Политика конфиденциальности и 152-ФЗ. Мы храним тренировки, вес тела и
  замеры, а с VK ID получим почту. Для оператора персональных данных
  обычно нужно уведомление Роскомнадзора и хранение данных в России —
  сервер на Reg.cloud этому соответствует, остальное проверить отдельно.
- Проходит ли модерацию название в сторе, отличающееся от подписи в
  лаунчере («Октус — дневник тренировок» против «Октус»).
