# RuStore

Как выложить приложение в RuStore и продавать подписку. Документация
изучена 29 сентября 2026 года; ссылки — внизу.

## Главное: самозанятому продавать нельзя

С 1 февраля 2026 года платёжные инструменты RuStore (платные приложения,
подписки, покупки внутри приложения) доступны только ИП и юрлицам. У
самозанятого Pay SDK не работает, платные приложения скрываются с витрины,
списания по подпискам останавливаются. Публиковать и обновлять бесплатные
приложения самозанятый может.

Отсюда порядок работ:

1. Публикуемся как есть, самозанятым, бесплатным приложением. Это
   закрывает всё, что не про деньги: подпись, модерация, карточка, политика
   конфиденциальности.
2. Перед подпиской — стать ИП. Регистрация бесплатная, 3–5 дней в налоговой
   плюс около 3 дней на постановку на учёт. Нужна усиленная
   квалифицированная электронная подпись (Рутокен). Налог на НПД 4–6%
   сохраняется и для ИП. Затем письмо в support@rustore.ru с темой
   «Сохранить текущий VK ID и обновить правовой статус»: 1–2 рабочих дня,
   приложения переезжают в аккаунт ИП, новые версии выпускать не нужно.
3. Встраиваем Pay SDK и серверную проверку.

Комиссия RuStore — 15%.

## Публикация

Требования консоли:

| Что | Требование | У нас |
|---|---|---|
| Файл | APK или AAB, до 5 ГБ, подписан | подписи нет, см. ниже |
| Версии | та же подпись, `versionCode` больше предыдущего | `versionCode 1` захардкожен |
| Название | до 30 символов, уникальное, совпадает с установленным | «Октус — дневник тренировок», 26 символов; в лаунчере «Октус» — уточнить у модерации, допустимо ли |
| Краткое описание | до 80 символов | нет |
| Полное описание | до 4000 символов, по-русски | нет |
| Иконка | 512×512, PNG/JPG, до 3 МБ, совпадает с иконкой лаунчера | есть исходник `pwa-assets/logo.png` |
| Скриншоты | от 3 на тип устройства, 9:16 или 16:9, реальный интерфейс, не только сплэш или логин | нет |
| Контакты | хотя бы один: почта, группа VK, сайт, MAX | нет |
| Политика конфиденциальности | обязательна | нет; положить на лендинг |
| Возрастной рейтинг, категория | выбрать в консоли | «Спорт» |

Правила модерации, которые нас касаются:

- Подписка: часть функций должна работать без неё, цена показана заранее.
  Совпадает с разделением free/paid из TODO.
- Вход: модератор должен пройти авторизацию без сторонних ресурсов;
  тестовый доступ пишется в комментарии для модератора. У нас вход
  необязательный, приложение работает на анонимном аккаунте.
- Без кликбейта в названии («лучший», «единственный»), без чужих товарных
  знаков в описании. Риск по знаку «Октус» — в
  `design/branding/README.md`.

### Подпись

`android/app/build.gradle` не знает про release-ключ: `npm run apk:release`
собирает неподписанный APK. Нужно:

- сгенерировать keystore один раз и хранить вне репозитория с резервной
  копией: потеря ключа означает, что обновления больше не выпустить;
- `signingConfig` читает путь и пароли из `android/keystore.properties`
  (в `.gitignore`) или переменных окружения — чтобы подписывать и в CI;
- та же подпись нужна для проверки платежей: Pay SDK требует, чтобы
  приложение было подписано тем же ключом, что и опубликованное в консоли.

APK проще AAB: подписываем сами, отдаём один файл, тот же файл ставится
на телефон для проверки.

До первой публикации решить, менять ли `appId` (`ru.ashlanderr.gymtracker`):
после неё идентификатор пакета не меняется.

## Подписка: Pay SDK

Старый BillingClient SDK выключен 1 августа 2026 года, платежи через него
не проходят. Актуален только Pay SDK, сейчас версия 11.1.0.

- Нативный SDK — Kotlin/Java: `ru.rustore.sdk:pay` через BOM
  `ru.rustore.sdk:bom:2026.08.01`. Есть обёртки для React Native, Flutter,
  Unity и других, для Capacitor нет. Найденный
  `maningame/capacitor-rustore-billing` построен на мёртвом BillingClient.
  Значит, пишем свой локальный Capacitor-плагин в `android/` — тонкую
  обёртку над `getProducts`, `getPurchases`, `purchase`.
- В манифест: `meta-data` с ID приложения из консоли и deep link-схема для
  возврата из оплаты. Схема нужна и для входа через VK ID — завести одну на
  оба случая.
- Установленный RuStore не обязателен: SDK умеет платить через СБП и
  банковские приложения, покупать можно без авторизации в RuStore.
- Подписки — только одностадийный платёж. Периоды настраиваются в консоли:
  пробный, промо, основной, grace и hold. Триал и грейс-период на неудачное
  списание — это настройка продукта, не наш код.
- Песочница с тестовыми картами. Карта с балансом 1 копейка проверяет
  переход в grace/hold после триала.

## Сервер

Статус подписки решает сервер, клиент только кэширует его на оффлайн.

- Ключ API создаёт владелец или администратор компании в консоли: вкладка
  компании → «API RuStore». Приватный RSA-ключ хранится у нас, публичный —
  в RuStore.
- `POST https://public-api.rustore.ru/public/auth/` меняет подписанный
  запрос на JWE-токен на 900 секунд. Токен передаётся в заголовке
  `Public-Token`/`API-key` — сверить по странице метода при реализации.
- Проверка покупки — по `invoiceId`/токену подписки. Есть серверные
  уведомления о смене статуса платежа, их стоит принимать, чтобы не опрашивать.
- Тот же API загружает APK, создаёт черновик версии и отправляет на
  модерацию — выкладку можно встроить в CI.

## Не проверено

- Политика конфиденциальности и 152-ФЗ. Мы храним тренировки, вес тела и
  замеры, а с VK ID получим почту. Для оператора персональных данных
  обычно нужно уведомление Роскомнадзора и хранение данных в России —
  сервер на Reg.cloud этому соответствует, остальное проверить отдельно.
- Проходит ли модерацию название в сторе, отличающееся от подписи в
  лаунчере («Октус — дневник тренировок» против «Октус»).
