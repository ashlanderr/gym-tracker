# Дизайн тренировки

Макеты статические, без сборки. Открываются как есть, но видео на `file://`
не всегда играет — проще поднять сервер из этой папки:

```bash
python -m http.server 8901 --directory design
```

| Файл | Что там |
|---|---|
| `workout-screen.html` | Основной макет: экран подхода, отдых, шторки веса и повторов, страница тренировки |
| `exercise-page.html` | Страница упражнения — техника, прогресс, история |
| `workout-finish.html` | Завершение тренировки, три состояния |
| `weights-variants.html` | Снаряды: стиль, единицы, тонкая настройка стека |
| `difficulty-variants.html`, `difficulty-weight.html` | Поиск формы вопроса о тяжести подхода |
| `workout-title.html` | Центрирование названия и размер видео |
| `workout-simple-mock.html`, `workout-reps-variants.html`, `workout-target-variants.html` | Ранние итерации, оставлены как история |

## Философия

**Экран отвечает на один вопрос: что мне делать прямо сейчас.** Всё, что не
является ответом на него, по умолчанию невидимо.

1. По умолчанию — только ответ. Ни таблиц, ни лент, ни счётчиков «на всякий случай».
2. Остальное живёт за тапом по тому объекту, к которому относится.
3. Ничего не всплывает само. Единственное исключение — таймер отдыха, он следующий шаг того же сценария.
4. Не спрашивать, если можно посчитать.
5. В основном потоке нет терминов. RIR, 1ПМ и диапазоны живут в статистике, куда приходят сознательно.
6. Заметность соответствует необходимости: то, без чего тренировка не идёт, подсказывается; необязательная глубина обходится шевроном.

## Три режима

| Режим | Глагол | Что умеет |
|---|---|---|
| Фокус на подходе | **делать** | Провести тренировку от начала до конца, и больше ничего |
| Страница упражнения | **узнать** | Только чтение плюс одно действие — замена |
| Таблица (нынешний UI) | **менять** | Состав, порядок, подходы, таймеры |

Таблица остаётся именно как режим редактирования — роль настоящая, отдать её некому.

## Решения

**Экран подхода.** Видео 190px с кропом по фигуре, играет само, тап — пауза.
Название — кнопка с шевроном, шеврон вынесен из потока, чтобы слова центровались.
Числа: `60 кг × 8`, оба белые, под повторами — «цель 6 – 8», под весом пусто,
кроме дня прибавки. Пунктир = «значение можно поправить», шеврон = «откроется страница».

**Кнопка.** «Сделал / Сделала» по профилю, «Сделано» пока род неизвестен.
«Готово» отвергнуто: причастие без подлежащего читается и как «я готов».
На последнем подходе кнопка **не меняется** — меняется подпись над числами.

**Отдых.** Одно число во весь экран. Вопрос «Как прошёл подход?» всегда с четырьмя
ответами: Легко · Норм · Тяжело · Отказ. Короткие слова — потому что перенос был
проблемой текста, а не вёрстки. Клавиши нарисованы теми же кнопками, что «−15/+15».
Частота вопроса падает по мере накопления истории. «Дальше» — голый факт, без пометок.

**Веса.** Геометрия из `WeightsVisualizer`, смягчённая: блины сидят на грифе,
номиналы повёрнуты внутри. Единица измерения — там, где число измеряет предмет
целиком (гриф, гантель, плитка стека), и не на номиналах блинов. Тонкая настройка
тренажёра — плашка над стеком, одна на любой механизм. Собрать нельзя: число
человека — не рисуем ничего, наше число — зовём в инвентарь.

**Страница упражнения.** Три вкладки. Прогресс открывается на среднем э1ПМ за
тренировку — единственной метрике, которая замечает добитый повтор в слабом
подходе. Провалы в дни прибавки не сглаживаются. История — вся, без фильтра.

**Завершение.** Манекен с тёплой шкалой (оттенок несёт данные, яркость остаётся
за иерархией), счётчик тренировок, три числа без сравнения с прошлым разом.
Якорь экрана — «в следующий раз»: рекорды бывают редко, план есть всегда.

**Цвета.** Зелёный — только кнопка фиксации. Синий — выбор. Жёлтый — разминка и
медаль рекорда, различаются формой. Яркость — иерархия.

## Что упирается в модель данных

- **История по слоту, а не по упражнению.** Второй жим в программе не должен
  получать веса от первого. Показывать можно всё, считать — по слоту.
- **Три владельца параметров:** упражнение (что это, какое оборудование),
  слот программы (подходы, повторы, таймер), зал (какие веса физически есть).
- **`tracking`** у упражнения: `weight_reps | reps | time | distance`. Экран с двумя
  числами предполагает железо, планка и подтягивания его ломают.
- **Периодизации не будет** — удаляется вместе с `PeriodizationSelector`,
  цветными полосками и веткой `periodization/` в рекомендациях.

## Ассеты

- Манекен: MIT-полигоны из [react-native-body-highlighter](https://github.com/HichamELBSI/react-native-body-highlighter),
  веб-порт — [react-body-highlighter](https://github.com/giavinh79/react-body-highlighter).
  Совпадают 16 из 17 значений `MuscleType`; широчайших отдельным полигоном нет.
- Видео упражнений: 480p H.264 ≈ 25–55 КБ на ролик. При 200 упражнениях это ~5–10 МБ,
  то есть влезает в бандл и offline-first сохраняется. VP9 на такой картинке
  проигрывает H.264.
- `Montserrat` объявлен в `index.css`, но нигде не загружается — приложение всё
  время рисуется системным шрифтом. Оптические подгонки текста подобраны под него.
